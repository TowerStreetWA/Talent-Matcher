# Vacancy ingestion & freshness — detailed reference

## Providers & pipeline

- `lib/vacancies/`: employerSiteProvider (Firecrawl careers-page crawl, concurrency 3), googleJobsProvider (SerpApi, `SERPAPI_API_KEY`; paginates `next_page_token` ≤20 pages; first uncached query slow — retry hits cache), dedupe.ts (cluster = normalized title+company; preference: direct_employer > legacy > google employer-domain > google aggregator > job_board > agency), ingestionRunner.ts (idempotent by sourceUrl; canonical swap transactional).
- **No LinkedIn crawler** — "LinkedIn Jobs Crawler" is a seeded demo source. Google Jobs results with linkedin.com apply links are attributed to "LinkedIn Jobs (via Google)" (`sourceProvider: linkedin_via_google_jobs`; dedupe ranks unchanged). See `docs/linkedin-audit.md`.
- Config: `config/employerSites.ts` (careers URLs rot — curl-probe before debugging extraction), `config/ingestionPatterns.ts` (sector×location patterns, extend coverage there), `config/ingestionFreshness.ts` (expiry thresholds: google/linkedin 14d, company_site 21d, default 30d).

## ATS providers

- `lib/vacancies/ats/`: 7 platforms via public JSON/RSS job-board endpoints — Lever, Ashby, Workable, SmartRecruiters, Recruitee, Teamtailor, Workday (CXS POST). Employers config-only in `config/atsEmployers.ts` (token, optional workdayInstance/workdaySite, maxJobs cap 100 default 40, locationIncludes filter, sectorTag). sourceType direct_employer, providers `ats_<platform>`; per-employer failures → warnings, not fatal. iCIMS excluded (no stable public JSON). Board tokens rot like careers URLs — curl-probe first.

## Careers-directory engine

- Generic, multi-sector: `lib/directory/engine.ts` (types, `atsEntryFromUrl` for all 7 ATS incl. workday locale-skip + lever-eu, `makeDirectoryEmployerProvider` routing ATS → basic HTML crawler → Firecrawl fallback, `selectDirectoryEmployers` shared-board dedupe).
- Seed employers may set `locationIncludes` (substring filter on all paths: ATS structured locations, and on crawler/Firecrawl paths matched across locationText+title+URL slugs like `-in-london-`) to keep global boards UK-scoped; boards that hide locations (Cloudflare "Hybrid", Accenture Workday null locationsText) filter to 0 by design — see seed `notes` + `lib/directory/resolveCareersBoard.ts` (careers→board resolution for JS-heavy sites: redirect-follow 15s/512KB, HTML board-link scan, unsupported-ATS detection greenhouse/icims/etc., 24h in-memory cache).
- Registry `config/careersDirectories.ts`: london_insurance (prefix `london_insurance`, 189 employers) + 5 seed directories banking/pensions/asset_management/accountancy_finance/it_tech (prefix `directory_<industry>`, 133 employers from `config/data/careers-directory-seed.json` → generated `careersDirectorySeedEmployers.ts` via `pnpm --filter @workspace/scripts run generate:careers-directory` — never hand-edit).
- UK-relevant global names added July 2026: banking segments investment_bank/international_bank/central_bank, big tech + IT consultancies, global asset managers — all careers URLs curl-probed before adding; bot-blocked sites (Meta, PIMCO, Infosys, TCS) noted in seed, need Firecrawl. July 2026 banking/it_tech push: ~20 employers upgraded/added with verified direct ATS boards (probe the public JSON API before trusting a token — greenhouse/ashby tokens can be non-obvious, e.g. ashby `checkout.com`, `thought-machine`); no-ATS employers (Wise, Revolut, Darktrace, Snyk, ClearScore) carry needs-Firecrawl notes in the seed; OakNorth (ashby) + Endava (smartrecruiters, UK-filtered) gained real boards July 2026. Provider keys `<prefix>_<segment>`, sourceType direct_employer.
- Basic HTML crawler (`lib/directory/basicHtmlCrawler.ts`): SSRF-safe static-page fetch + anchor/table extraction (ROLE_SIGNAL_PATTERN role-noun gate, marketing-link filters, `titleFromAnchor` anti-glue, badge-suffix strip); JS-heavy shells detected → Firecrawl only then. Firecrawl no-credits circuit breaker in `lib/firecrawl.ts` (`firecrawlUnavailability()`, 30-min backoff on "insufficient credits", clears on success) → outcome `needs_firecrawl` instead of hammering a dead upstream. Per-process `lib/directory/ingestionPathRegistry.ts` (7-day TTL, pruned on write) feeds coverage diagnostics: `ingestion_paths` {by_path/by_outcome/firecrawl_available/firecrawl_unavailable_reason} + per-zero-job-employer `last_ingestion` on GET `/internal/debug/careers-directory-coverage`.
- London Insurance Market directory: canonical md at `src/config/data/London-Insurance-Market-Directory.md` → generated `config/londonInsuranceEmployers.ts` (regenerate via `pnpm --filter @workspace/scripts run generate:london-directory`). `lib/vacancies/londonDirectory.ts` is a thin wrapper over the engine (LONDON_SEGMENTS, londonProviderKey, atsEntryFromCareersUrl etc. preserved). Provider keys `london_insurance_<segment>` unchanged.
- Directory endpoints (admin+, internal): POST `/internal/ingestion/careers-directory` ({directory, segments?, employers?, offset?, limit ≤25}, default 5/batch, per-employer funnel, failures recorded + continue); POST `/internal/ingestion/careers-directory/resolve` ({directory,...} or {urls ≤10}) returns CompanyRecord[] (resolution outcomes, no ingestion); legacy POST `/internal/ingestion/london-insurance-directory` delegates (audit action unchanged). GET `/internal/debug/careers-directory-coverage?directory=` (industry totals, per-segment counts, by_source, zero-job employers with platformHint + cached resolution outcome); london coverage endpoint delegates (compat: `directory` key = config block). Hourly sweep `lib/directory/directorySweep.ts` (same advisory lock 743291652, per-directory hour slots idx%slots, opt-in: only tenants with an existing `<prefix>_%` source; config errors abort that directory's tick).

## Job boards

- `reedProvider.ts` (reed_api, Basic auth `REED_API_KEY` as username, DD/MM/YYYY dates) and `adzunaProvider.ts` (adzuna_api, `ADZUNA_APP_ID`/`ADZUNA_APP_KEY`, gb endpoint, strips `<strong>` markup); both sourceType job_board (dedupe already ranks below direct_employer). Query patterns config-only in `config/jobBoardPatterns.ts` (REED_PATTERNS/ADZUNA_PATTERNS, cap ceiling 200; incl. banking + it_tech role-level patterns). Google Jobs patterns (`config/ingestionPatterns.ts`) cover all six sector tags incl. it_tech role queries.

## Internal endpoints & freshness

- Internal admin+ endpoints (deliberately NOT in OpenAPI): POST `/internal/ingestion/{employer-sites,google-jobs,run-patterns,expire-stale,ats,reed,adzuna}` — run patterns one per curl call (multi-pattern HTTP runs exceed safe duration); `/ats` takes `{platforms?, companies?}` (one platform per call), `/reed` + `/adzuna` take `{query,location?,maxResults?}` or `{patterns?}` (default: all configured patterns).
- Expiry sweep (`expirySweep.ts`): every 6h, advisory xact lock, expires ingestion-backed jobs past freshness thresholds; manual/demo jobs never expire. `jobs.last_seen_at` bumped on re-discovery (discoveredAt = first-seen). `job_sources` has is_demo/provider/last_fetch_count/last_new_count/last_refreshed_count; JobSource DTO exposes the funnel (jobCount = activeJobs); Sources card shows "Last run: X fetched · Y new · Z already tracked".
- Job attribution is first-provider-wins by sourceUrl: shared careers boards (Markel Intl→Markel Syndicate Workday board, DUAL Group→Howden/Hyperion board, Hiscox coverholder→ats_workday) mean a segment source can legitimately show 0 jobs while "fetching" plenty — all its fetches refresh rows owned by the source that found them first. The MGA & coverholders segment is the canonical example: its only job-yielding employers share boards with syndicate/broker entries, and the rest are static pages with no listings or JS-heavy pages needing Firecrawl.
- `jobs.sector_tag` stores the ingestion pattern's sector; query-time classification is the fallback.

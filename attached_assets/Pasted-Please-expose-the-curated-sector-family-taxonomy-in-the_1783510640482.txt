Please expose the curated sector/family taxonomy in the Job Search UI so recruiters can filter by industry and function using the taxonomy you’ve just implemented.

GOAL

We now have:

- Unified curatedTitles schema and per-industry files for:
  - insurance
  - banking
  - pensions
  - asset_management (fund managers + real assets)
  - accountancy_finance
- Sector-aware tagging and ?sector= filters (including accountancy_finance).
- Families encoded via tags (e.g. underwriting, claims, investment_banking, portfolio_management, audit_assurance).

This phase should:

1) Make **sector filters** visibly selectable in Job Search (chips/dropdowns).
2) Surface **family/function filters** (e.g. Underwriting, Claims, Investment Banking, Portfolio Management) based on the taxonomy.
3) Wire these filters cleanly through:
   - the search API,
   - URL/query params,
   - saved searches,
   - and the curated taxonomy.

Do not change auth, billing, or candidate matching flows.

====================================
1. SECTOR FILTERS IN JOB SEARCH
====================================

Implementation:

- In the Job Search page (/job-search):
  - Add a visible sector selector:
    - Examples (non-exhaustive — use existing enum):
      - Insurance
      - Banking
      - Pensions
      - Asset Management
      - Accountancy & Finance
      - (Any other existing sectors you have)
  - Likely UI patterns:
    - sector chips (toggleable, single-select),
    - or a sector dropdown with clear labels.

- Wire sector selection to:
  - the existing `sector` query parameter used by GET /api/jobs/search (?sector=insurance, ?sector=accountancy_finance, etc.),
  - the URL (so sector filters are shareable/bookmarkable),
  - saved job searches (sector stored and restored correctly).

- Ensure that:
  - Unknown sectors still produce a 400 at the API level (as now),
  - The frontend does not allow selection of unknown sectors (options should match OpenAPI enum).

Acceptance:

- Recruiters can easily filter Job Search by sector using chips/dropdowns.
- Sector choice is reflected in the URL and saved searches.
- API calls match the selected sector, and sector-specific tagging is honoured.

====================================
3. USING CURATED TITLES IN FILTERS
====================================

Tie filters to the taxonomy:

- Use the curatedTitles schema (curatedTaxonomies / helpers) to:

  - determine which families are present for a given sector,
  - ensure only families that actually have titles for that sector are offered as filters.

- Do not hardcode random families that don’t exist in the taxonomy.

For example:

- For `industry: "insurance"`, derive family set from insurance entries (e.g. underwriting, claims, broking_distribution, risk_compliance, etc.).
- Use a display mapping to convert internal family keys to human-friendly labels:

  - `"underwriting"` → "Underwriting"
  - `"broking_distribution"` → "Broking & Distribution"
  - `"fpna_commercial"` → "FP&A & Commercial Finance"

Maintain a mapping in a config file (e.g. config/curatedTitles/displayFamilies.ts) so labels can be changed without touching core logic.

====================================
4. UX DETAILS
====================================

- Sector and family filters should:

  - be clearly visible but not overwhelming,
  - play nicely with existing keyword/location filters,
  - be easy to clear (Clear All button, or per-chip removal).

- Zero-result states:

  - When sector + families + keywords produce zero jobs:
    - Show a constructive message referencing filters:
      - e.g. “No jobs found for Insurance → Underwriting in London. Try removing some filters or broadening your search.”

- Ensure:

  - Filters don’t reset unexpectedly when navigating or saving searches.
  - URL reflects current filters so links/bookmarks preserve context.

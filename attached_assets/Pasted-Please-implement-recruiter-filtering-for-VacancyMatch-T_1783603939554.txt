1. RECRUITER REGISTRY CONFIG
====================================

Create a recruiter registry config, e.g.:

Structure:

- notes (optional)

Never hardcode logic around recruiters in multiple places — use this registry everywhere.

====================================
2. COMPANY CLASSIFICATION: DIRECT VS RECRUITER
====================================

Add/extend a company classification step so each company gets a `company_kind` like:

- 'direct_employer'
- 'recruitment_firm'
- 'job_board'
- 'unknown'

Classification rules:

1) Hard-match registry:

- If company name or domain matches the recruiter registry, classify as 'recruitment_firm'.

2) Website signals (for companies not in registry):

- Use homepage/careers/about text snippets to detect recruiter phrases, e.g.:
  - "recruitment agency"
  - "staffing solutions"
  - "employment agency"
  - "executive search"
  - "we are a recruitment consultancy"
  - "temp and perm"
  - "specialist recruiters"
- If multiple strong signals are found, classify as 'recruitment_firm'.

3) Job-post signals:

- In job descriptions/company snippets, look for patterns like:
  - "our client"
  - "on behalf of our client"
  - "we are recruiting for"
  - "specialist recruitment consultancy"
- If the employer name is absent/obscured but the posting entity is a recruiter, classify accordingly.

4) Fallback:

- If none of the above match, leave company_kind as 'direct_employer' or 'unknown' as appropriate.

Ensure classification runs in the existing directory/ingestion pipeline so `company_kind` is stored with each job’s company reference.

====================================
3. SEARCH FILTERING BEHAVIOUR
====================================

Update search so that:

- By default, search results exclude jobs where:
  - company_kind = 'recruitment_firm'
- Optionally, add a UI toggle:
  - "Include recruitment firms" (or "Show recruiter jobs")
  - When enabled, include recruiter jobs but **clearly label them** as recruiter-sourced (e.g. badge "Recruitment firm").

Implementation:

- In the job search query builder:
  - add a default condition: `company_kind != 'recruitment_firm'`
  - unless a query option `includeRecruiters = true` is set.
- Ensure this applies consistently across:
  - Job Search in the app
  - Saved searches / alerts
  - Any other recruiter-facing queries, unless explicitly overridden.

Do NOT delete recruiter jobs; just filter them at query time.

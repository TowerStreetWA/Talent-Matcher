# VacancyMatch AI — Replit Prompt for Source Truthfulness, Freshness, and Insurance Taxonomy

Please implement a refinement phase for VacancyMatch AI focused on source truthfulness, freshness, ingestion transparency, and curated insurance job-title taxonomy support.

## GOAL

We have completed the ingestion audit and discovered that the old “LinkedIn Jobs Crawler” source in the Sources panel is not a real crawler — it is a seeded demo row with static demo counts. This caused misleading expectations.

A compliant real path is now in place via Google Jobs pagination + attribution of LinkedIn-hosted jobs as “LinkedIn Jobs (via Google)”.

This phase should:
1. Remove or clearly relabel the fake LinkedIn seeded source so it cannot be mistaken for a live ingestion source.
2. Add expiry/inactive logic so jobs do not remain active forever when no longer re-discovered.
3. Improve the Sources page so it shows a clearer ingestion funnel:
   - fetched
   - active
   - canonical
   - duplicates
   - last successful run
4. Add a config-driven taxonomy layer for curated industry job-title lists, starting with insurance, using the supplied insurance title list below.

Do not change candidate matching, billing, or auth.

## PART 1 — SOURCE TRUTHFULNESS

### Objective
Ensure the Sources page accurately represents real ingestion sources.

### Implementation

- Find the seeded demo source row for “LinkedIn Jobs Crawler”.
- Either:
  - remove it completely from production/demo source displays, or
  - relabel it very clearly as a seeded/demo source so no one can mistake it for a live source.
- Prefer removing it from normal production-facing UI if possible.
- Ensure the real source “LinkedIn Jobs (via Google)” is shown where relevant.
- Audit other source cards too and confirm none of them are misleading seeded placeholders.

### Acceptance
A user looking at Sources should immediately understand which sources are real, which are derived, and which are demo-only.

## PART 2 — EXPIRY / INACTIVE LOGIC

### Objective
Jobs should not stay active forever if they stop appearing in ingestion runs.

### Implementation

- Add a freshness model for ingested jobs, for example:
  - track `last_seen_at` on each vacancy/source record,
  - mark jobs inactive if not re-discovered within a configurable threshold.
- Make the threshold configurable by `source_type` / `source_provider` if feasible.
  Example:
  - Google Jobs: inactive after X days not seen
  - Company career sites: inactive after Y days not seen
  - LinkedIn Jobs (via Google): inactive after Z days not seen
- Add a background/internal sweep job that:
  - checks all active jobs,
  - marks stale jobs inactive,
  - records counts of jobs inactivated per source.
- Do this additively, without breaking existing canonical logic.

### Acceptance
Jobs that disappear from source feeds eventually become inactive and no longer inflate active counts forever.

## PART 3 — SOURCES PAGE: FUNNEL METRICS

### Objective
Make the Sources page more transparent and useful.

Update each source card to show some or all of:

- fetched (latest run or rolling recent total)
- active jobs
- canonical jobs
- duplicates merged
- last successful run
- source type / provider
- source health/status

If necessary, add a lightweight source metrics structure or endpoint to support this.

### Important

- Keep the UI clean and readable.
- Do not overload the cards with too much text.
- If needed, show the core metrics on the card and fuller detail in a modal or drawer.

At minimum, the user should be able to tell:
- how many jobs came in,
- how many are currently active,
- whether the source is healthy,
- when it last really ran,
- and why canonical active counts may be lower than raw fetched counts.

Also add concise help text/tooltips where useful:
- “Active” = currently active and not stale
- “Canonical” = deduplicated jobs shown in search/matching

### Acceptance
The Sources page clearly communicates why a source might fetch 240 jobs but expose fewer canonical active jobs.

## PART 4 — CURATED INSURANCE JOB TITLE TAXONOMY

### Objective
Add a config-driven taxonomy structure for curated industry job-title lists, starting with insurance.

### Implementation requirements

- Add a file/config-driven taxonomy layer.
- Support at least these fields:
  - industry
  - family
  - canonicalTitle
  - variants
  - optional seniority
  - optional tags

A good target structure would be JSON or TypeScript config objects like:

```ts
{
  industry: "insurance",
  family: "underwriting",
  canonicalTitle: "Underwriter",
  variants: ["Assistant Underwriter", "Junior Underwriter", "Senior Underwriter"],
  seniority: "mixed",
  tags: ["underwriting"]
}
```

- Create a dedicated insurance taxonomy file/place to store the supplied curated insurance job titles.
- Use this taxonomy in at least one meaningful part of the system:
  - search normalization, and/or
  - sector/function tagging, and/or
  - ranking boosts, and/or
  - candidate-side role inference

For this phase:
- implement the structure and loader
- paste and structure the supplied insurance title list below
- wire it into the search/tagging pipeline in a testable way

Do not build admin UI for this. File/config-driven is preferred.

Please implement the next careers-directory phase for VacancyMatch / Talent Matcher:

1) add support for more ATS platforms the resolver already detects, and
2) expose sector scorecard diagnostics so we can see coverage quality by industry.

GOAL

Turn currently detected-but-unsupported ATS boards into real job sources, and give us a single scorecard endpoint that shows how healthy each sector is (seeded employers, ingestion paths, jobs, and gaps).

PRIORITY ATS PLATFORMS

Focus first on ATS that the resolver already flags as unsupported_ats:

- Greenhouse
- iCIMS
- SuccessFactors

If feasible, also prepare hooks/config for:

- Taleo
- Personio
- BambooHR
- Rippling
- JazzHR
- Comeet

====================================
1. ADD ATS SUPPORT
====================================

Implementation:

1) Extend ATS URL parsing & provider detection so Greenhouse, iCIMS, and SuccessFactors are recognised as first-class providers (not “unsupported”).

2) For each new ATS:

- create/extend provider modules under the existing ATS-fetch layer (similar to Workday / Lever / Teamtailor / Recruitee):
  - parse job listings from public JSON/HTML endpoints or stable feeds,
  - normalise into the existing jobs schema:
    - title
    - company
    - location
    - description/summary
    - applyUrl
    - discoveredAt / lastSeenAt
    - sectorTag / industry linkage where available
- integrate with:
  - atsEntryFromUrl
  - makeDirectoryEmployerProvider
  - careers→board resolution
  - ingestion metrics / source health

3) Keep routing rules:

- ATS-backed employers → ATS fetchers first
- basic HTML crawler → for static non-ATS pages
- Firecrawl → ONLY for JS-heavy pages when neither ATS nor basic HTML can extract jobs

4) Diagnostics:

- update the coverage / directory endpoints so Greenhouse/iCIMS/SuccessFactors appear as normal ATS providers, not “unsupported_ats”.

Acceptance:

- At least one live employer per new ATS (e.g. a Greenhouse company, an iCIMS company, a SuccessFactors company) is successfully resolved and ingested.
- Previously “unsupported_ats” cases move into the ATS-ingested path where boards are accessible.

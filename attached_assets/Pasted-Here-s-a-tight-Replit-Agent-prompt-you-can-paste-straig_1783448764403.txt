Use Firecrawl to ingest jobs from company websites:
•	Start with a configurable list of employers and career-page URLs (e.g. a small seed table or config file).

•	Identify job list pages and job detail pages.
•	For each job detail page:
•	Extract structured fields:
•	title
•	company
•	location
•	description
•	employment_type
•	salary_text
•	remote_type
•	posted_at (if available)
•	source_url
•	Mark  source_type = direct_employer ,  source_provider = company_site .

(Ref: Google job posting structured data docs.)

3. Google Jobs discovery
Add a Google Jobs provider for broader coverage:
•	Implement a provider that can query Google Jobs via a third‑party search API (e.g. SerpApi’s Google Jobs endpoint), not via raw scraping.
•	Given a query (title, location) and optional company name, retrieve a structured list of job results.
•	For each result:
•	Extract fields similar to above.
•	Set  source_type = google_jobs .
•	Set  source_provider = google_jobs_serpapi  (or similar).
•	Store  source_url  pointing at the job detail page, ideally on the employer domain if available.
We should abstract the provider behind an interface so future providers (job boards, others) can be added without changing core logic.

Deduplication and source preference
Implement a vacancy dedupe/canonicalization layer:
•	For new candidate vacancies:
•	Normalize:
•	job title
•	company name
•	location
•	contract type
•	Identify likely duplicates:
•	same (or very similar) title
•	same company (normalized)
•	similar location
•	similar salary_text (if available)
•	For duplicate clusters, select a canonical vacancy record.
Canonical preference order:
1.	 direct_employer  (company careers site)
2.	 google_jobs  where  source_url  is on the employer domain
3.	 job_board  (future)
4.	 agency  (future)
Store:
•	one canonical record per cluster (used for matching),
•	with a list of “backing sources” (e.g. JSON field or join table) so we know it also appears on boards/Google Jobs.
In this phase, we only need the canonical record and maybe a simple list of source URLs. Keep the structure minimal but extendable.
